  • ❌ 蓝牙遥控 — 竞赛禁止遥控，但 USART 中断接收框架可复用于视觉数据接收

    • 需新增的核心模块：视觉通信协议解析、PID 速度/方向闭环、状态机调度、顶点检测逻辑

3.4 视觉通信协议 (K230 ↔ MCU)

数据帧格式 (自定义)

帧头 偏差(DL) 偏差(DH) 置信度 顶点标志 校验和 帧尾 0xAA [低8位] [高8位] [0-100] [0/1] [XOR] 0x55 ───────────────────────────────────────────────────── 共 7 字节，每帧 10ms 发送一次 (100Hz) 偏差值 (int16): 正值=偏右, 负值=偏左, 范围 ±500 0 = 完全居中 置信度 (uint8): 0=丢失, 100=极高置信度 顶点标志(uint8): 0=非顶点, 1=检测到顶点交叉/弯道特征

设计要点:

  • 帧头 0xAA / 帧尾 0x55 双字节保护，防止误识别
  • 校验和 = 偏差(DL) ^ 偏差(DH) ^ 置信度 ^ 顶点标志，用于验证数据完整性
  • MCU 端实现超时检测：连续 50ms 无有效帧 → 视觉丢失告警 → 减速停车
  • K230 视觉端同时输出：线偏差、是否为顶点区域、置信度

4.3 顶点检测策略 (A/B/C/D 识别)

核心思路: 场地路径中，每个顶点是「弧线端点」—— 路径曲率在该位置发生显著变化。视觉算法无需识别字母标记，而是通过检测路径拓扑特征来判定顶点。

检测方法组合:

  1. 曲率检测: 跟踪黑线方向角变化率。弯道顶点处曲率达到极值
  2. 方向突变: 弧线起始点处，黑线方向会从直线转向曲线（或反向）
  3. 消失/出现: 有些顶点处黑线会"消失"出视野边界（方向改变超出 ROI）
  4. 路径计数: 状态机记录当前已行驶的路径段编号，结合视觉特征判定到达哪个顶点

顶点去抖机制:

到达 A 点后，短暂锁死检测 (300ms)，防止重复触发。每经过一个顶点，状态机切换到下一个目标路径段。

4.4 K230 代码框架 (MicroPython 示例)

# ===== K230 视觉巡线 ===== import sensor, image, time from machine import UART uart = UART(2, baudrate=115200) # 与 STM32 通信 sensor.reset() sensor.set_pixformat(sensor.RGB565) sensor.set_framesize(sensor.QVGA) # 320x240 sensor.skip_frames(20) ROI_NEAR = (0, 160, 320, 80) # 近端 ROI_MID = (0, 80, 320, 80) # 中端 ROI_FAR = (0, 0, 320, 80) # 远端 def find_line_center(img, roi): """在 ROI 区域内查找黑线中心列""" blob = img.find_blobs([(0,50)], roi=roi, pixels_threshold=200) if blob: return blob[0].cx() # 中心列坐标 return None while True: img = sensor.snapshot() img.gaussian(1) # 自适应阈值分割 img.binary([(0, 60)], invert=False) centers = [] for roi in [ROI_NEAR, ROI_MID, ROI_FAR]: cx = find_line_center(img, roi) centers.append(cx) # 计算加权偏差 deviation = 0 if centers[0]: deviation = 160 - centers[0] # 基于近端 # 顶点检测 (简化: 曲率突变) vertex_flag = 0 if prev_dev is not None: delta = abs(deviation - prev_dev) if delta > 80: # 偏差突变 → 可能是顶点 vertex_flag = 1 # 发送数据包 send_packet(deviation, vertex_flag) prev_dev = deviation time.sleep_ms(10) # 100Hz

⚠ 关键难点: 要求三/四的对角直线段 (A→C, B→D)

场地中 A→C 和 B→D 之间没有黑色引导线，小车必须依靠以下方案完成对角直线行驶:

导航手段原理精度
陀螺仪航向锁定 JY901S 提供绝对航向角(Yaw)。出发前根据目标点计算目标航向角（A→C: ≈-141°或+39°，取决于坐标系定义），PID 闭环锁定该航向 角度误差 < 1°
编码器里程计 累积编码器脉冲，计算行驶距离。A→C 约 128cm 时判定到达（对角距离 = √(100²+80²) ≈ 128.1cm） 距离误差 < 5cm
视觉辅助定位 摄像头持续监测前方，当目标区域的黑色弧线端点进入视野时，切换为巡线模式进行精确逼近 末端修正

对角直线行驶流程:

  1. 计算航向: 已知 A(60,100)→C(160,20)，航向角 = atan2(20-100, 160-60) = atan2(-80, 100) ≈ -38.7°，换算为陀螺仪 Yaw 角后锁定
  2. 直线行驶: 陀螺仪 Yaw PID 控制方向，视觉暂停巡线（因为地面无黑线），编码器累计距离
  3. 接近目标: 编码器计到 ~110cm 时减速，视觉模块开始搜索前方黑色弧线端点
  4. 切换巡线: 视觉检测到黑线 → 切换为巡线模式 → 精确沿弧线到达 C 点 → 声光提示

5.4 路径状态机 (含双模式导航)

typedef enum { // --- 导航子模式 --- MODE_LINE_FOLLOW, // 视觉巡线: 黑线可见，用视觉偏差控制方向 MODE_DEAD_RECKON, // 航位推算: 无黑线，用陀螺仪锁定航向+编码器计距 } NavMode_t; typedef enum { TASK_IDLE = 0, // 要求1 TASK_1_AB, // A→B (巡线, 100cm) // 要求2 (顺时针一圈, 全程巡线) TASK_2_AB, // A→B (巡线, 100cm) → 到B声光 TASK_2_BC, // B→C (巡线, 右弧~125.7cm) → 到C声光 TASK_2_CD, // C→D (巡线, 100cm) → 到D声光 TASK_2_DA, // D→A (巡线, 左弧~125.7cm) → 到A声光+停车 // 要求3 (对角+弧线, 混合模式) TASK_3_AC, // A→C (航位推算, 对角~128cm, 目标航向≈-38.7°) → 到C声光 TASK_3_CB, // C→B (巡线, 右弧~125.7cm, 沿右弧上行) → 到B声光 TASK_3_BD, // B→D (航位推算, 对角~128cm, 目标航向≈-141.3°) → 到D声光 TASK_3_DA, // D→A (巡线, 左弧~125.7cm, 沿左弧上行) → 到A声光 // 要求4 TASK_4_LAPS, // 要求3路径 × 4圈, lap_count=0..3 TASK_DONE } TaskState_t; // 每个状态定义: // .mode = MODE_LINE_FOLLOW 或 MODE_DEAD_RECKON // .target_dist = 目标距离 (cm), 仅 MODE_DEAD_RECKON 有效 // .target_yaw = 目标航向角 (°), 仅 MODE_DEAD_RECKON 有效 // .next_vertex = 下一个要到达的顶点 (A/B/C/D) // .on_arrival = 到达后的处理 (声光/停车/切换状态)

5.5 双模式导航控制切换

┌─────────────────────────────────────────────────┐ │ 主循环 10ms │ │ │ │ if (当前为 MODE_LINE_FOLLOW): │ │ ├─ 偏差 = 视觉模块串口数据 │ │ ├─ 方向PID输入 = 视觉偏差 │ │ ├─ 顶点检测: 视觉标志位 OR 编码器里程辅助 │ │ └─ 到达顶点 → 声光 → 切换到下一状态 │ │ │ │ if (当前为 MODE_DEAD_RECKON): │ │ ├─ 误差 = 目标Yaw - 当前Yaw (陀螺仪) │ │ ├─ 方向PID输入 = 角度误差 (归一化到±180°) │ │ ├─ 距离 = 编码器累计 │ │ ├─ if 距离 > 目标距离*0.85: │ │ │ ├─ 减速 + 视觉搜索黑线 │ │ │ └─ 检测到黑线 → 切换 MODE_LINE_FOLLOW │ │ └─ if 距离 > 目标距离+超时: 停车报错 │ │ │ │ 速度PID (两种模式共用): │ │ 左轮PWM = 基础PWM + 差速量/2 │ │ 右轮PWM = 基础PWM - 差速量/2 │ └─────────────────────────────────────────────────┘ 设计要点: · 对角段 A→C 起步时，小车从 A 点出发，已知 A=(60,100), C=(160,20) · 出发前设定: 目标Yaw = atan2(20-100, 160-60) = -38.7° (需转换为陀螺仪坐标系的实际角度) · B→D 段: 目标Yaw = atan2(20-100, 60-160) = atan2(-80, -100) ≈ -141.3° · 两段对角距离相同: √(100²+80²) ≈ 128.1cm (约 129cm 含余量)

5.6 停车控制策略

精准定点停车

  1. 减速段: 当视觉检测到距目标顶点 < 20cm 时，线性减速 (500ms 内降到低速)
  2. 微调段: 低速接近，速度降至 20%
  3. 停车条件: 视觉偏差 ≈ 0 且 持续 100ms 稳定 → 立即刹车
  4. 声光提示: 蜂鸣器响 200ms + LED 闪烁 3 次

7.2 关键调试点

视觉端调试

  • K230 IDE 实时预览分割效果
  • 上位机显示偏差值曲线
  • 录制视频回放分析漏检帧
  • 不同光照条件下测试阈值鲁棒性

控制端调试

  • 串口实时打印目标/实际/偏差
  • SerialPlot 软件观察 PID 响应曲线
  • OLED 屏幕显示关键状态
  • 录制慢动作视频分析运动稳定性

系统联调

  • 先用简单直线测试视觉→PID 链路
  • 再用单弯道测试方向控制
  • 最后用完整弧线测试顶点检测
  • 统计连续运行成功率 (≥ 90%)

7.3 备选方案 (Plan B)

如果 K230 视觉方案遇到困难:

  • 降级为 OpenMV: OpenMV Cam H7 更成熟，IDE 集成度高，社区资源丰富
  • MCU 降级: 如果 STM32F4 开发遇到困难，先用 ESP32-S3 替代（自带 Wi-Fi/BLE 调试方便）
  • 路径简化: 先完成要求一 (A→B)，验证核心视觉巡线链路，再逐步扩展
  • 速度保守: 在功能验证阶段使用较低速度 (50% 额定值)，功能跑通后再提速
