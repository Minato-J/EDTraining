# H0 赛题项目分析总结报告

> **项目**: 2026年全国大学生电子设计竞赛 — 武汉工程大学校内选拔赛 H0 赛题  
> **日期**: 2026年5月  
> **主控平台**: STM32F407VET6

## 一、项目概述

本项目针对 2026 年全国大学生电子设计竞赛（电赛）武汉工程大学校内选拔赛 **H0 赛题**，要求设计并制作一辆智能小车，在指定的椭圆形场地（由直线段与半圆弧段组成）上，按照 A、B、C、D 四个节点自动行驶，完成多个不同路线与约束的行驶任务。

项目基于 **STM32F407VET6** 微控制器，采用 K230 视觉模块进行 6 路灰度循迹，JY901S 陀螺仪进行角度姿态保持，TB6612 双 H 桥驱动左右轮电机，编码器用于速度闭环，构成了一套完整的 **感知—决策—执行** 闭环控制系统。

### 4.2 双模切换策略

| 条件 | 激活模式 | 控制方式 | 说明 |
|------|----------|----------|------|
| `line_sensor_data == 0x00`（K230 无黑线信号） | **模式A — 盲开模式** | 陀螺仪 Yaw 角 → 角度环 PID 保持直线 | 在圆弧段或丢线时依赖惯性导航 |
| `line_sensor_data != 0x00`（K230 检测到黑线） | **模式B — 循迹模式** | K230 偏差量 → 角度修正 → 角度环 PID | 精确跟踪黑线路径 |

这一策略保证了小车在黑线可见时以视觉为主导，在黑线不可见时以陀螺仪惯性导航为辅，避免失控。

### 4.4 TIM6 中断服务（约 20 ms 周期）

TIM6 定时器以约 **20 ms** 为周期触发中断，是整个控制系统的核心节拍。在中断服务函数中依次执行：

1. 读取左右编码器计数值，经低通滤波得到实际轮速
2. 接收并解析 K230 视觉数据，获取黑线偏差量与传感器状态
3. 检测黑线状态变化（有→无 或 无→有），更新节点计数 `count`
4. 根据当前任务阶段和 `count` 值，设置 `target_angle` 与 `base_speed`
5. 执行角度环 PID 计算，输出角度修正量
6. 执行左右轮速度环 PID 计算，输出 PWM 占空比
7. 将 PID 合成结果写入 TB6612 电机驱动

## 六、核心算法解析

### 6.1 PID 控制器

系统使用 **增量式 PID** 控制器，通过结构体 `PID_TypeDef` 统一管理多路 PID 参数与状态。

**控制公式**（增量式）:

```
Δu(k) = Kp × [e(k) - e(k-1)] + Ki × e(k) + Kd × [e(k) - 2e(k-1) + e(k-2)]
u(k) = u(k-1) + Δu(k)
```

**参数配置**:

| PID 环路 | Kp | Ki | Kd | 输出限幅 | 控制目标 |
|----------|:--:|:--:|:--:|:--------:|----------|
| 左轮速度环 | 0.9 | 0.12 | 0.0 | ±500 | 跟踪左轮目标转速 |
| 右轮速度环 | 0.8 | 0.12 | 0.0 | ±500 | 跟踪右轮目标转速 |
| 角度环 | 1.2 | 0.0 | 0.6 | ±40 | 保持/修正目标偏航角 |

**设计要点**:

- **速度环**采用 PI 控制（Kd=0），因为编码器噪声较大，微分项会引入不稳定因素
- **角度环**采用 PD 控制（Ki=0），比例项快速纠偏，微分项抑制振荡，无需积分项（避免积分饱和）
- 左右轮速度环 Kp 略有差异（0.9 vs 0.8），用于补偿两个电机的机械差异
- 输出限幅防止 PID 输出过大导致电机饱和

### 6.2 双模切换算法

双模切换是本项目循迹策略的核心创新点。由于场地包含直线段和圆弧段，黑线可能在某些位置不可见（如圆弧过渡区域），因此设计了两种控制模式的自动切换机制：

```c
// 伪代码
if (line_sensor_data == 0x00) {
    // 模式A: 盲开模式
    // 无黑线信号 → 依靠陀螺仪维持当前航向
    angle_error = target_angle - gyro_yaw;
    angle_out = PID_Calc(&angle_pid, 0, angle_error);
} else {
    // 模式B: 循迹模式
    // 检测到黑线 → 使用K230偏差量修正航向
    angle_correction = turn_amount * track_kp;
    angle_out = PID_Calc(&angle_pid, 0, angle_correction);
}
```

**切换逻辑**:

- 当 K230 的 6 路灰度传感器全部未检测到黑线（`line_sensor_data == 0x00`）时，切换至盲开模式，陀螺仪以当前目标角度为基准维持直线
- 一旦任一灰度传感器检测到黑线，立即切换至循迹模式，根据 K230 计算的偏差量进行转向修正

**优势**: 该策略在直线段可充分利用视觉精确循迹，在圆弧段或丢线瞬间依靠陀螺仪惯性导航平滑过渡，两者互补，保证了行驶的连续性和稳定性。

### 6.3 节点计数算法

节点计数用于判断小车当前行驶到了哪个节点，从而触发任务状态机的阶段切换。

**原理**: 在 TIM6 中断（20 ms 周期）中检测黑线状态的**边沿变化**：

```c
// 伪代码
static uint8_t last_line_state = 0;  // 上一次黑线状态

if (last_line_state != 0 && line_sensor_data == 0x00) {
    // 从"有线"变为"无线" → 驶离一个节点
    count++;
} else if (last_line_state == 0 && line_sensor_data != 0x00) {
    // 从"无线"变为"有线" → 进入一段新的路线
    // 可选计数
}

last_line_state = line_sensor_data;
```

**计数逻辑**: 小车每经过一个节点（黑线交叉点），传感器会经历"检测到黑线 → 黑线消失"的变化过程，利用这一边沿触发计数。不同的 `count` 值对应不同的节点位置，任务状态机据此切换 `target_angle`（目标航向角）和 `base_speed`（基础速度）。

### 6.4 任务状态机

任务状态机由 `task.c` 实现，通过按键选择任务编号，启动后在 TIM6 中断中根据 `count` 值推进阶段：

```
[按键选择任务]
       │
       ▼
[等待启动 PB1]
       │
       ▼
[阶段1: 初始化角度/速度]
       │ count 达到阈值
       ▼
[阶段2: 更新角度/速度]
       │ count 达到阈值
       ▼
[阶段3: 更新角度/速度]
       │ ...
       ▼
[完成: 停车 + 声音提示]
```

每个阶段核心操作：
- 设置 `target_angle`（如直线段保持 0 度，圆弧段切换到特定角度）
- 设置 `base_speed`（如直道加速、弯道减速）
- 根据 `count` 值判断是否到达下一节点，到达时发出蜂鸣器声音提示

- 取消任务(2)的注释，调试阶段切换逻辑
- 确定半圆弧段的目标角度值（左半圆弧和右半圆弧分别对应的 `target_angle`）
- 调整弯道行驶速度（`base_speed`），确保圆弧段不脱线
- 确保到达 C、D、A 各节点时有声音提示

#### 高优先级 — 任务(3) 实现

- 实现 A → C 直线段的控制逻辑
- 实现 C → B 半圆弧段的转弯控制
- 实现 B → D 直线段的控制逻辑
- 实现 D → A 半圆弧段的转弯控制
- 重点优化"最少停车次数"：研究在不停车的情况下完成连续弯道过渡的策略

#### 中优先级 — 任务(4) 实现

- 分析赛题对"恰好停车 4 次"的具体要求
- 设计停车时机策略（哪些节点停车、停车时长）
- 实现精确的停车控制（编码器速度归零 + 短暂延时）

### 8.2 控制策略优化

| 优化方向 | 具体措施 |
|----------|----------|
| **PID 参数调优** | 在实际场地上精细调整三组 PID 参数，特别是角度环的 Kp 和 Kd |
| **圆弧段控制** | 圆弧段不能仅靠"盲开"直线保持，需要研究设定合理的 `target_angle` 使其沿弧线行驶 |
| **速度曲线优化** | 引入梯形或 S 形速度曲线，在接近节点时平滑减速，提高停车精度 |
| **节点检测鲁棒性** | 增加去抖逻辑，避免因传感器抖动导致 `count` 多计或漏计 |
| **丢线恢复策略** | 在长时间无黑线信号时，增加回找策略（如小幅摆动搜索） |

### 8.3 可靠性与鲁棒性提升

- **通信校验**: K230 和 JY901S 的串口数据增加 CRC 校验或帧完整性检查，防止数据帧错位
- **看门狗保护**: 启用 IWDG 硬件看门狗，防止程序跑飞
- **编码器异常处理**: 检测编码器计数异常（如突然归零或溢出），加入容错机制
- **电池电压监测**: 增加 ADC 电压检测，低电量时自动降低 `base_speed` 或报警
