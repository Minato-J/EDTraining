## 二、核心架构差异总览

两个项目共享相同的硬件平台（STM32F407VET6 + K230 + JY901S + TB6612），底层驱动文件（Motor、Encoder、PID、WIT_IMU、OLED）完全一致，**核心差异集中在 `task.c` 任务状态机和 `main.c` 中断回调的控制逻辑上。**

## 三、逐文件详细对比

### 3.1 task.c — 最大差异所在（核心变化）

#### 3.1.1 导航策略根本不同

**H0 版本：连续曲线循迹**
- 所有任务（Task 2/3/4）都基于"黑线循迹 + 目标角度修正"的连续控制
- `Run_Task_2()` 走 A→B→C→D→A：直线段用角度保持，圆弧段设置 target_angle（如 -185°、+185°），依靠 K230 视觉持续修正航向
- `Run_Task_3()` 走 A→C→B→D→A：直线段设对角线角度（-45°、-135°），圆弧段同样设目标角度
- 圆弧段使用 `ff_diff`（前馈差速）来辅助转弯，左转时右轮快，右转时左轮快

**第四问完成 版本：航点到航点（Waypoint-to-Waypoint）**
- 到达路口后完全停车，原地旋转到目标角度，然后直线冲刺到下一个路口
- 不再依赖 K230 视觉进行圆弧段的连续循迹
- 每个航点之间使用"停车→旋转→直行"三步走策略
- 用 `wait_tick` 计时器控制原地旋转等待时间（固定 10 个 tick × 10ms = 100ms，注释说是 700ms，实际上可能需要调参）

#### 3.1.2 任务映射完全重新分配

| 任务编号 | H0 版本 | 第四问完成 版本 |
|---------|--------|----------------|
| Run_Task_1 | A→B 直线（基本要求1，15分） | **A→C→B→D→A 三圈**（发挥2，20分），完整 29 个状态（state 0~28） |
| Run_Task_2 | A→B→C→D→A 全圈（基本要求1+2） | A→C→B→D→A 单圈（发挥2），9 个状态（state 0~8） |
| Run_Task_3 | A→C→B→D→A 全圈（发挥2） | A→B→C→D→A 简化版（**圆弧段 target_angle 被注释掉**，未完成） |
| Run_Task_4 | A→C→B→D→A ×4圈 | A→B 简单直线（仅 count==0/1，极简） |

**关键发现：第四问完成版的 Task 1 是最核心的实现，对应赛题发挥部分第 2 问（A→C→B→D→A，20 分），已经可以跑 3 圈。**

#### 3.1.3 状态机设计差异

**H0 版本的状态机（Task 2 为例）：**
```
count=0: A→B 直线 (target_angle=0, base_speed=60, ff_diff=0)
count=1: B→C 圆弧 (target_angle=-185°, base_speed=40, ff_diff=10)
count=2: C→D 直线 (target_angle=180°, base_speed=60, ff_diff=0)
count=3: D→A 圆弧 (target_angle=+185°, base_speed=40, ff_diff=-10)
count=4: 停车
```
特点：仅通过 count 切换段，无停车/旋转，全程连续运行。

**第四问完成版的状态机（Task 1 单圈，state 0~7）：**
```
state 0: A点停车，原地旋转到 -38°（等待 wait_tick>=10）
state 1: 直线冲刺到 C 点（target_angle=-38°, base_speed=60）
state 2: C点停车，扭头到 0°（等待 wait_tick>=10）
state 3: 直线冲刺到 B 点（target_angle=0°, base_speed=30）
state 4: B点停车，大调头到 -144°（等待 wait_tick>=10）
state 5: 直线冲刺到 D 点（target_angle=-144°, base_speed=60）
state 6: D点停车，回正到 180°（等待 wait_tick>=10）
state 7: 直线冲刺回 A 点（target_angle=180°, base_speed=30）
```
特点：每个路口完全停车再启动，用 IMU 精确旋转，不走圆弧。

**三圈循环（Task 1 完整实现）：**
```
第一圈: state 0~7  → 到达 A 后跳转 state 10
第二圈: state 10~17 → 到达 A 后跳转 state 20
第三圈: state 20~27 → 到达 A 后进入 state 28 停车
```
每圈的 state 编号独立（0~7, 10~17, 20~28），允许为不同圈单独微调参数。

#### 3.1.4 角度策略差异

**H0 版本：连续角度跟踪**
- 直线段：设置固定目标角度（0°、-45°、135° 等）
- 圆弧段：设置大角度目标（-185°、+185°），依赖角度环 PID 跟踪
- 角度环 PID 参数：Kp=1.2, Kd=0.6, limit=40

**第四问完成 版本：离散角度跳转**
- A→C 方向：-38°（而不是 H0 的 -45°）
- C→B 方向：0°（向右水平）
- B→D 方向：-144°（而不是 H0 的 -135°）
- D→A 方向：180°（向左水平）
- 第三圈的 B→D 方向微调为 -147°（state 25），可能是实测调参结果

**角度差异分析：**H0 版本用的是理想几何角度（-45°、-135°），第四问完成版用的是实测角度（-38°、-144°），说明后者经过了实际场地校准。

#### 3.1.5 速度策略差异

**H0 版本：**
- 直线段 `BASE_SPEED_STRAIGHT` = 60
- 圆弧段 `BASE_SPEED_CURVE` = 40
- 圆弧段额外叠加 `ff_diff`（前馈差速 ±10）

**第四问完成 版本：**
- 直线段速度 = 60（高速冲刺）
- 航点间短距离段速度 = 30（低速稳定，如 C→B、D→A）
- 无 ff_diff（因为不走圆弧，不需要差速补偿）
- 每圈的各段速度可以独立调整（因为状态编号独立）

#### 3.1.6 节点计数去抖差异

**H0 版本（main.c 中）：**
```c
if (count_debounce > 0) count_debounce--;
uint8_t current_line = (line_sensor_data != 0x00);
if (last_line_status == 1 && current_line == 0) {
    if (count_debounce == 0) {
        count++;
        count_debounce = 10; // 200ms 去抖窗口
    }
}
last_line_status = current_line;
```
有完善的 200ms 去抖机制，防止同一路口重复计数。

**第四问完成 版本（main.c 中）：**
```c
uint8_t current_line = (line_sensor_data != 0x00);
if (last_line_status == 1 && current_line == 0) {
    count++;
}
last_line_status = current_line;
```
无去抖！每次黑线→白线转换都直接 count++。这是因为该版本在路口会完全停车旋转，物理上避免了重复计数的问题。

#### 3.1.7 task.h 差异

**H0 版本** 额外导出了 `count_debounce`、`ff_diff`、`lap_count` 变量。
**第四问完成 版本** 的 task.h 更简洁，`lap_count` 和 `wait_tick` 被定义为 `static` 或在 main.c 中用 `extern` 引用。

### 3.2 main.c — 中断回调差异

两个版本的 `main.c` 差异很小：

| 差异点 | H0 | 第四问完成 |
|--------|-----|----------|
| `extern uint8_t lap_count;` | 无（lap_count 在 task.c 中定义，未 extern） | 有（在 main.c PTD 区 extern 声明） |
| OLED 第四行 | 无 | 新增 `OLED_ShowSignedNum(48, 48, lap_count, 4, 16, 1)` 显示圈数 |
| 节点计数去抖 | 有 200ms debounce 机制 | 无 debounce，直接 count++ |
| TIM6 中断注释 | `// == 中断测试 ==` | 相同 |
| 其余逻辑 | 完全相同 | 完全相同 |

### 3.3 k230_track.c — 转向灵敏度表差异

**H0 版本（原始灵敏度）：**
```
微偏:  ±3      中度: ±6~9     重度: ±10      极度: ±18~27
default: turn_speed = last_turn  // 记住上次值
```

**第四问完成 版本（调整后灵敏度）：**
```
微偏:  ±2~4    中度: ±6~7     重度: ±10      极度: ±14~18
default: break  // 不记住上次值，返回 0
```

主要变化：
1. 整体降低了转向增益（最大值从 27 降到 18），因为第四问版本主要在直线段使用 K230，不需要过激的修正
2. `default` 分支改为 `break`（不再保持 last_turn），对全白/全黑的异常状态直接归零
3. 注释更规范，分类为"微偏/中度偏/重度偏/极度偏"

### 3.4 完全相同的文件

以下文件两个版本完全一致，无任何差异：
- `Motor.c/h` — 电机驱动
- `encoder.c/h` — 编码器读取
- `pid.c/h` — 增量式 PID
- `wit_imu.c/h` — JY901S 陀螺仪解析
- `main.h` — 引脚定义

### 3.5 main.c 初始化对比

PID 参数完全相同：
- 左轮速度环：Kp=0.9, Ki=0.12, Kd=0, limit=500
- 右轮速度环：Kp=0.8, Ki=0.12, Kd=0, limit=500
- 角度环：Kp=1.2, Ki=0, Kd=0.6, limit=40

## 四、架构设计思路差异总结

### H0 版本的设计思路："连续曲线循迹"
- 沿赛道黑线连续运行，不停车
- 圆弧段靠角度环 PID 跟踪目标角度
- 直线段靠 K230 视觉纠偏
- ff_diff 前馈差速辅助圆弧段
- 需要精细调参角度环 PID 和 K230 灵敏度
- **优点**：理论上速度快（不停车）
- **缺点**：圆弧段角度控制难度大，容易脱线；PID 调参复杂

### 第四问完成 版本的设计思路："路口停车旋转"
- 到达路口后完全停车，用 IMU 精确旋转到下一段方向
- 直线冲刺到下一个路口
- 不走圆弧，完全避免了弯道控制难题
- 用固定等待时间（wait_tick）控制旋转
- **优点**：实现简单可靠，不会在弯道脱线；角度控制精度高
- **缺点**：每次停车重启浪费时间；wait_tick 固定值可能不够精确

## 六、关键待改进方向

### 从第四问完成版本出发，要拿更高分需要：

1. **实现精确停车（发挥 1，10 分）**：在起跑线位置检测到特定标志后精确停车，可以利用 K230 识别起跑线的特殊标记（如横向黑线）

2. **恢复 A→B→C→D→A 路径（基本要求 1，15 分）**：需要把 H0 的 Task 2 圆弧段逻辑融合进来，或者在第四问完成版的状态机基础上，增加走圆弧的旋转角度设置

3. **实现三次通过起跑线逻辑（发挥 3，30 分）**：
   - 第一次通过：识别起跑线但不停车，继续前进
   - 第二次通过：精确停车，等待 3 秒后重新启动
   - 第三次通过：精确停车，结束比赛
   - 需要增加 `lap_pass_count` 计数器和 3 秒延时逻辑

4. **实现变速策略（发挥 4，40 分）**：不同圈可以设置不同 `base_speed`，利用第四问完成版的每圈独立状态编号可以方便实现

5. **修复 wait_tick 时间问题**：当前 `wait_tick >= 10` 实际只等待 100ms（10 × 10ms），注释说 700ms 可能不准确，需要根据实际旋转速度调参

6. **角度微调**：第三圈 B→D 段已经用了 -147°（而不是 -144°），说明角度还在持续调优中
