# H0 + 第四问完成 最优合并方案（修订版）

## 一、目标

将 **H0（连续循迹版）** 与 **第四问完成（航点停车版）** 的最佳设计融合，产出一个**稳定可靠、赛题得分最大化**的统一版本。

---

## 二、取舍决策：保留什么，抛弃什么

### 2.1 从第四问完成保留（核心导航策略）

| 保留项                  | 理由                                    |
| -------------------- | ------------------------------------- |
| **航点到航点策略**          | 路口停稳→IMU 旋转→直线冲刺，比圆弧连续循迹**可靠得多**      |
| **多圈状态机框架**          | 每圈独立 state 编号，可逐圈微调参数                 |
| **实测角度值**            | -38°、-144°、-147° 是**场地实测**结果，不是几何计算值  |
| **wait_tick 旋转等待**   | 简单有效，~700ms 原地旋转稳定                    |
| **29 状态三圈机**         | 最完整的实现，A→C→B→D→A 路线已跑通，可直接作为赛题(3)基础   |
| **K230 保守参数**        | 微偏±2~4、中度±6~7，直线段更稳定、不易振荡（详见 5.4 节分析） |
| **`default: break`** | 对未识别传感器状态安全归零，防止错误累积（详见 5.4 节分析）      |

**核心理由**：航点策略避免了弯道脱线的最大风险点，符合竞赛"稳定拿分 > 追求速度"的原则。

### 2.2 从 H0 保留（增强鲁棒性）

| 保留项                             | 理由                                  |
| ------------------------------- | ----------------------------------- |
| **节点去抖 `count_debounce`**       | 200ms 窗口防止黑线边沿误触发，航点策略同样需要          |
| **前馈差速 `ff_diff`**              | 直线段保留为 0，弧段可选叠加差速辅助转弯               |
| **K230 `last_turn` 记忆（仅 0x00）** | `0x00`（全白脱线）时保持上次转向值，维持方向惯性直到重新找回黑线 |
| **全 4 任务启用**                    | Task_Dispatcher 四路全开，按赛题编号对应        |

### 2.3 降级为可选策略（不完全抛弃）

| 项目               | 处理方式               | 理由                                                          |
| ---------------- | ------------------ | ----------------------------------------------------------- |
| **H0 圆弧连续循迹**    | 降级为**可选编译开关**，默认关闭 | 有其他实验组通过调参成功；作为航点策略的速度优化替代方案，通过 `ENABLE_ARC_CONTINUOUS` 宏切换 |
| **H0 K230 激进参数** | 保留在代码注释中作为调优参考     | 若场地光线变化需要更大修正力，可快速切换                                        |

**圆弧连续循迹降级的深层原因**（不是抛弃，而是需要更严谨的修复才能用）：

H0 圆弧连续循迹不稳定的根源：

1. **±185° 角度目标语义错误**：IMU Yaw 角包装在 -180~+180，设置 -185° 后经角度规范化会产生错误的误差值，PID 输出完全不可预期
2. **双模切换架空角度环**：K230 模式下 `target_angle = current_angle` 实时同步，角度环 PID 的目标被覆盖，实际只有 K230 + ff_diff 在起作用
3. **ff_diff ±10 未场地标定**：硬编码的值与弧半径、车速、地面摩擦力强相关，未在不同条件下测试

**修复后可用的前提**：将弧段 target_angle 改为终点方向角度（而非歧义的绝对值），增大 ff_diff 主导转弯，并降低角度环 Kp。届时只需打开 `ENABLE_ARC_CONTINUOUS` 宏即可启用。

### 3.5 赛题4 停车代码注释说明

原 `Run_Task_1`（29状态三圈）每个节点都有：

```c
base_speed = 0;
target_angle = -38.0f;  // 或 0°, -144°, 180°...
wait_tick++;
if (wait_tick >= 10) {  // 700ms 等待
    ...
    current_state = next;
    wait_tick = 0;
}
```

改为不停车版本时，将 `wait_tick` 等待逻辑注释掉，改为条件满足后**立即跳转**：

```c
// 示例：state 0 改为不停车
case 0:
    base_speed = 60;         // 保持速度
    target_angle = -38.0f;   // 保持角度
    // 原 wait_tick 旋转等待 → 注释掉
    // 直接进入行驶状态
    count = 0;
    current_state = 1;       // 立即进入下一状态
    break;
```

> **注意**：三圈共 12 个旋转等待点（state 0/2/4/6/10/12/14/16/20/22/24/26），全部注释掉后小车将连续行驶不停车，仅在检测到 count 变化时切换状态。

| 0x30 / 0x03 | 极偏最外侧 2 位 | **±16**         | **取中间值**（H0 ±18 vs 第四问 ±14） |
| 0x20 / 0x01 | 极偏单边最外    | **±20**         | **取中间值**（H0 ±27 vs 第四问 ±18） |
| **0x00**    | 全白脱线      | **last_turn**   | **H0 策略**（保持方向惯性）           |
| **default** | 未识别状态     | **break (返回0)** | **第四问完成策略**（安全归零）           |

#### 5.4.2 为什么微偏~中度采用保守参数？

1. **合并方案中 K230 的作用域已被缩小**：航点策略下 K230 只在直线段使用，不需要 H0 激进参数来应付弧段。直线段的目标是维持航向，小幅修正足以抵消缓慢漂移。

2. **激进参数在直线上的振荡风险**：turn_speed=27 在 base_speed=60 时产生 54 个单位差速（一侧 ±45%），在高速直线行驶中会导致车身侧摆→惯性过冲→蛇形振荡。

3. **微偏值的物理对应**：1 位偏移（0x08/0x04）对应黑线偏离中心约 1/6 ROI（~106px），在赛道黑线宽约 2cm 时对应实际偏离 2-3cm。turn_speed=2（差速 4）的修正力足以在 200-400ms 内拉回中线。

#### 5.4.3 为什么极偏值取中间值（±16~20）？

- H0 ±18~27 过激（base_speed=30 时左轮几乎停转）
- 第四问完成 ±14~18 偏保守（base_speed=60 时恢复力不足）
- **取 ±16~20**：在完全脱线边缘时仍有足够恢复力，但不至于过度纠偏

#### 5.4.4 为什么 0x00 保留 H0 的 `last_turn`？

- `0x00` 意味着 K230 完全看不到黑线，小车可能正在经过交叉路口或在脱线边缘
- 此时保持上一次的转向方向（惯性维持）是最安全的选择
- 如果盲目归零（break），小车可能正好在脱线边缘放弃修正，彻底跑偏
- `last_turn` 给了一个"记忆中的正确方向"，直到 K230 重新看到黑线

#### 5.4.5 为什么 default 保留第四问完成的 `break`？

这是对比分析中最重要的安全决策之一。

**H0 的 `default: turn_speed = last_turn` 的风险**：

**风险场景 A：连续多帧噪声累积**（最危险）：

假设小车刚完成急转弯（`last_turn = 27`），K230 帧同步丢失，连续 5 tick 产生非法传感器值：

```
Tick 1: default→last_turn=27 → smooth=0.7×27≈19
Tick 2: default→last_turn=27 → smooth=0.3×19+0.7×27≈25
Tick 3: default→last_turn=27 → smooth≈26
Tick 4~5: ... → smooth≈27（完全饱和）
```

100ms 后 turn_out_smooth 稳定在 27，小车持续急转并脱线。而 `default: break` 下仅需 3 tick（60ms）smooth 值就归零，小车恢复直行。

**风险场景 B：弧段到直线段过渡残留**：

弧段结束时 `last_turn` 携带旧转向值（如 10），若过渡区传感器值为未覆盖值（0x1A/0x0D），旧转向值被错误传递到直线段。

**关键洞察**：`turn_out_smooth = 0.3f * old + 0.7f * new` 的低通滤波已经提供了 1-2 tick 的短期连续性。`last_turn` 提供的额外"惯性"本质上是**冗余且危险的**——滤波只衰减合法值，而 `last_turn` 会持续输出已经过时的值。

| 条件                | last_turn 惯性好   | last_turn 惯性坏   |
| ----------------- | --------------- | --------------- |
| 传感器短暂丢失（1-2 tick） | 无影响（smooth 已覆盖） | 无影响             |
| 传感器连续异常（3+ tick）  | **危险**：持续错误转向   | 归零安全            |
| 弧段到直线过渡           | 可能平滑但方向可能错误     | 归零后 smooth 自行恢复 |

**第四问完成 `break` 的安全性**：

- 对于任何未识别的传感器状态，返回 0 意味着"不做任何转向修正"
- 这是一个**保守且安全**的策略：不知道黑线在哪 → 不转向 → 保持当前方向直行
- 在 IMU 角度环的辅助下（盲开模式已在 0x00 时覆盖），default 分支到达的概率极低
- 即使到达了，不转向也比错误转向安全

**结论**：

- `0x00`（全白，K230 明确表示无信息）→ `last_turn`（**防御性编程**——实际上 `0x00` 在 main.c 的双模切换中已被拦截，不会进入此函数，但保留无害且符合防御性编码原则）
- `default`（异常值，K230 状态不确定）→ `break`/返回 0（不修正=安全，遵循**故障安全原则**）

#### 5.4.6 双模切换条件分析（保留现有设计 + 增强）

**现有切换条件**：`line_sensor_data == 0x00 → 陀螺仪盲开，否则 → K230 循迹`

**为什么这个条件是合理的**：

1. `0x00` 是唯一的"K230 无信息"状态——每个 ROI 都是白色，视觉系统彻底失去参照物
2. 只要至少 1 个 ROI 看到黑线，K230 就能给出有意义的偏差估计
3. 在航点策略下，直线段遇到 0x00 的概率很低，通常是经过节点或短暂反光
4. target_angle 同步机制确保切换瞬间无突变

**新增增强（两项）**：

1. **盲开超时保护**（见 5.3 节）：连续 1 秒无视野 → 紧急停车，防止永久脱线
2. **旋转阶段 K230 屏蔽**（见 5.3 节）：原地旋转时不看 K230，纯 IMU 控制
