# Issue 10: Task 4 航点状态机重构——从硬编码 29 状态到循环复用

## Parent

无 — 架构审查发现

## What

Task 4 当前实现为 29 个硬编码状态（state 0-7, 10-17, 20-28），每圈 8 个状态 × 3 圈 + 1 个终点停车。每圈的角度参数做微小调整以补偿电池电压下降（-38° → -34° → -37°）。

**问题**：
1. **脆弱的参数依赖**：每圈手动微调角度依赖于特定电池、地面摩擦力、轮胎气压。换个场地/电池，三个圈的角度参数全要重调
2. **不可扩展**：赛题(4) 要求 4 圈 → 需要新增 state 30-37，硬编码状态数增加到 37
3. **代码重复**：每圈的状态序列完全相同（A→C→B→D→A），只是角度参数微调。370 行代码中 ~300 行是重复的
4. **调试困难**：改一处（如 C→B 弧段速度），需要改 3（将来 4）个地方

### 重构方案：单圈模板 + lap_counter 循环

```
单圈模板（inline 或宏）:
  state 0: A 点起步 → target_angle = DIAG_AC_ANGLE
  state 1: A→C 推进 → 等 C 点
  state 2: C 点换向 → target_angle = 0
  state 3: C→B 推进 → 等 B 点
  state 4: B 点换向 → target_angle = DIAG_BD_ANGLE
  state 5: B→D 推进 → 等 D 点
  state 6: D 点换向 → target_angle = 180
  state 7: D→A 推进 → 等 A 点

Run_Task_4():
  phase = current_state / 8;   // 0=第一圈, 1=第二圈, ...
  step  = current_state % 8;   // 0-7 圈内步骤
  根据 phase 查表微调角度（如果还需要的话）
  switch(step) { ... }  // 单圈 8 状态
  到达 A 点时 lap_counter++，lap_counter >= 4 → 停车
```

### 角度微调策略（如果仍然需要）

如果逐圈微调确实有必要（电池电压下降导致实际循迹角度偏移），可以用查表代替硬编码：

```c
// 电池满电→亏电，对角线角度补偿表（实测标定）
static const float angle_compensation[4] = {0.0f, 4.0f, 3.0f, 1.0f};
// 使用: target = DIAG_AC_ANGLE + angle_compensation[lap];
```

但更可能的情况是：**不需要微调**。角度环 PID 本身就具有鲁棒性——只要 K230 能看到线，小车就会自动修正。原来的逐圈微调可能是过度优化。

### 与 Task 4 加圈的关系

Issue "Task 4 加第 4 圈" 应该基于本重构来做，而不是继续硬编码 8 个新状态。重构后加圈只需要改 `lap_count >= 4` → `lap_count >= 4`（已经是 4 圈），不需要加状态。
