# Domain Docs

工程技能在探索代码库时如何消费本仓库的领域文档。

## 探索前，先读取

- **`CONTEXT.md`**（仓库根目录）
- **`docs/adr/`** — 读取与当前工作领域相关的 ADR

如果以上文件不存在，**静默跳过**。不要标记它们的缺失，也不要建议立即创建。生产类技能（`/grill-with-docs`）会在术语或决策真正确定时延迟创建它们。

## 文件结构

单上下文仓库：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
└── src/
```

## 使用术语表中的词汇

当你输出涉及领域概念的内容（issue 标题、重构建议、假设、测试名称）时，使用 `CONTEXT.md` 中定义的术语。不要偏离到术语表明确避免的同义词。

如果需要的概念尚未出现在术语表中，这是一个信号——要么你在发明项目不使用的语言（重新考虑），要么确实存在空白（记录下来给 `/grill-with-docs`）。

## 标记 ADR 冲突

如果你的输出与现有 ADR 矛盾，明确指出来，而不是静默覆盖：

> _与 ADR-0007（xxx 决策）矛盾——但值得重新讨论，因为…_
